# Bitunix Martingale-Leverage Bot

Бот за Bitunix Futures (SOLUSDT по подразбиране):

- margin = **50% от баланса** на всяка сделка (`MARGIN_FRACTION`)
- TP **+1%** / SL **-0.5%** (за SHORT е обратното) — `TP_PCT`, `SL_PCT`
- ливъридж стълба **2x → 4x → 8x → 16x → 32x → 64x**: загуба = следващото стъпало (загуба на 64x → пак 2x); печалба = винаги обратно на 2x
- посока: две стратегии за избор (`STRATEGY=ema` или `STRATEGY=smc`, виж по-долу). SMC засича FVG/OB/BOS на таймфрейма от `SMC_TIMEFRAME` (по подразбиране **5m**, местят се с 1m/15m/30m/1h/...).
- след затваряне → пауза 5 сек → нова сделка, безкраен цикъл

## Два режима

| | `REAL_MONEY=false` (по подразбиране) | `REAL_MONEY=true` |
|---|---|---|
| Пари | виртуални (`PAPER_BALANCE=100`) | **реални** |
| Цени | реални, живи от Bitunix | реални |
| API ключове | не трябват | трябват |
| Такси + slippage | симулирани | реални |

Paper режимът симулира: изолиран margin, TP/SL по реалната цена, такси (0.06% на страна), slippage, приблизителна ликвидация. **Не симулира** funding такси и дълбочина на order book, затова резултатите са реалистични, но леко оптимистични.

**Превключване към реални пари:** в `.env` смени `REAL_MONEY=false` на `REAL_MONEY=true` (плюс API ключовете). Ботът показва предупреждение и чака 10 секунди преди да почне, за да можеш да го откажеш с `Ctrl+C`. Ако в стария ти `.env` има ред `PAPER_TRADING=...`, изтрий го — ако двете се противоречат, ботът отказва да стартира.

## Стратегии

**`STRATEGY=ema`** — EMA(9)/EMA(21) кросоувър. Винаги има посока, затова търгува постоянно.

**`STRATEGY=smc`** — детектори за Smart Money Concepts върху 5-минутни свещи (само затворени):
- **Структура (BOS / CHoCH):** затваряне на свещ над последния swing high = бичи пробив, под последния swing low = мечи. Първият пробив в обратна посока е CHoCH и обръща тенденцията.
- **FVG (Fair Value Gap):** три свещи, при които първата и третата не се застъпват → зона на „дисбаланс".
- **Order Block:** при пробив нагоре — свещта с най-ниския low между пробития swing high и пробиващата свещ (обратно при пробив надолу).
- **Liquidity sweep:** фитил отвъд последния swing, но затваряне обратно вътре.
- **Вход:** само по тенденцията (бичи структура → само LONG), когато цената се върне във **свежа** зона (FVG или OB, още неподбита и незатворена през нея). Точки: +1 за всяка зона, в която е цената, +1 за скорошен sweep. Изискват се минимум една зона и точки ≥ `SMC_MIN_SCORE`.
- Ботът **не е винаги в пазара** — чака сетъп и на 60 секунди пише ред `SMC: trend=... | nearest FVG ...`, за да видиш какво гледа. При вход пише `Entry reason: ...`.

Това е една конкретна механична интерпретация на понятия, които всеки трейдър чертае по своему. Ако не съвпада с начина, по който ги виждаш ти, дефинициите са в `bot/indicators.py`. Тестове: `python3 -m unittest discover -s tests -v`.

## Пускане на Mac

```bash
cd ~/Downloads/bitunix-martingale-bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
caffeinate -i python3 main.py
```

`caffeinate -i` не позволява на Mac-а да заспи, докато ботът върви. Спиране: `Ctrl+C`.

При `STRATEGY=ema` първите ~21 минути ботът събира цени; при `smc` изтегля последните 200 свещи веднага.

## Как да следиш баланса

- На всеки `BALANCE_LOG_SECONDS` (по подразбиране 5 мин.) в лога излиза ред `[PAPER] balance=$... (+X% vs session start $...) | leverage rung=...x` — така знаеш баланса дори докато ботът чака сетъп, не само след сделка.
- След всяка затворена сделка има и по-подробен ред: `PAPER | balance=... | win-rate=... | max-loss-streak=... | max-drawdown=...`
- В Railway: Project → твоят service → таб **Logs**, най-новите редове са отдолу.
- `paper_trades.csv` — история на всяка сделка. На Railway е на volume-a (не се вижда директно в браузъра); за да го изтеглиш: `railway link` после `railway run cat paper_trades.csv > paper_trades.csv` от терминала на Mac-а (изисква `railway` CLI: `npm i -g @railway/cli` или `brew install railway`).
- `bot_state.json` — състоянието (баланс, стъпало на ливъридж); изтрий го (или volume-a), за да почнеш наново с 100$.

По подразбиране `MAX_DRAWDOWN_FRACTION=0.5` спира бота при -50%. Сложи `0`, ако искаш да видиш paper акаунта докрай.

## Реално търгуване (едва след paper тест)

1. Bitunix → API Management → нов ключ (само Futures trading, **без** withdraw).
2. В `.env`: `BITUNIX_API_KEY`, `BITUNIX_API_SECRET`, `REAL_MONEY=true`.
3. Парите трябва да са във **Futures** wallet-а (USDT), не в Spot.
4. Започни с малък `MARGIN_FRACTION` (0.05–0.1).
5. Ако преди това си пускал paper, ботът сам започва с чисто състояние за live режима.

## Риск (честно)

- Без такси, при случайна посока и TP 1% / SL 0.5%, шансът за печалба е ~33% и очакваната стойност е **нула**. С такси и slippage (~0.16% от позицията на сделка) break-even win rate става ~44%, така че без реален edge в сигнала всяка сделка е леко минусова.
- Удвояването на ливъриджа не създава edge — то само увеличава размера на загубите точно в серия от поражения. При 64x ликвидацията е на ~1% движение, а SL е на 0.5%: при рязък скок цената може да прескочи SL.
- EMA кросоувърът е проста идея, не доказана стратегия. Затова е paper режимът: гледай го поне няколко дни, включително колко пъти стига 32x–64x.
- Това не е финансов съвет.
